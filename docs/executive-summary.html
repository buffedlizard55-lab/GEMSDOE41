Why this file avoids the range error

Every one of its 12,279,160 stored values is finite, with minimum 0 and maximum 1. There is no negative sentinel or NaN-valued nodata tag. Outside-footprint cells contain numeric zero and are null through an internal GeoTIFF mask matching the template. This reconciles the published null-outside requirement with safe numerical values.

This is the new H42 submission (GEMS41-H42-BasinMargin-DensityPack), not the archived H41 file. The exact cause of your earlier portal error is unknown without the rejected bytes. Out-of-range sentinel values are one possible cause; NaN alone is not proven to be the cause. We verified the current file rather than guessing about the old one.
