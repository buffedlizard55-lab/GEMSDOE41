What would be required before any future upload

  1. Re-read the official competition rules, metric, and file-format instructions and the currently published competition instructions.
  2. Build the intended file from the exact recorded input hashes. Run the independent local validator and inspect its receipt; do not edit the TIFF after validating it.
  3. Require a preregistered, spatially blocked holdout to beat the current best matched baseline under the project gate, including sensitivity checks, before spending a weekly slot. H41-A-R does not meet this requirement.
  4. Only after the gate is honestly passed, sign in to DrivenData through your own account, open New submission, select the single-band GeoTIFF, and paste the exact internal name and note. Never send credentials to this repository or put them in chat.
  5. After an actual upload, record the organizer-returned score, submission timestamp, leaderboard row, and uploaded-file hash separately. Do not infer a competition score from a local proxy.

Known limitations

  • No candidate support reached the four held-out interiors, so H41-A-R has no matched-mass DTI. A null result is not evidence that its score is zero or positive.
  • The 300 m exclusion can omit genuine new-fault corrections near existing traces.
  • Strike and endpoint estimates come from 100 m rasterized faults, not original trace geometry; regional family names do not establish local slip sense.
  • The orientation signal is derived from detrended elevation and is not an independently mapped fault-lineament dataset.
  • Input integrity is pinned against a public owner-maintained mirror; the login-gated DrivenData inputs were not authenticated in this environment.
